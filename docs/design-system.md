# Design system

Code-only (markdown) design canon: no Figma/Pencil MCP is configured for this project. Component
choices are recorded here as they're built or extended, so a later feature reuses what exists
instead of re-inventing it.

## Registered components

| Component | Location | Contract | Used by |
|---|---|---|---|
| `LoadError` | `components/layout/content-area/load-error.tsx` | A segment `error.tsx` boundary's plain-language "We couldn't load your data" state: an `Empty` (icon + title + description) plus a "Try again" `Button` that calls the caller's `onRetry`. Takes a `retrying` prop (the boundary's `useTransition` `isPending`): while it — or an async `onRetry` — is in flight, the button shows a `Spinner` and is disabled, so a double click can't retry twice (SCR-17 `retrying`). Takes an optional `errorDigest`, carried for future support tooling but never rendered — a load failure's raw message must never reach the screen (AC-28). | Any route segment's `error.tsx` (screens.md §SCR-17) |
| `ConfirmationModal` | `components/modals/global-modals/confirmation-modal/confirmation-modal.tsx` | Base `Dialog` (title/description/footer Cancel+Confirm) extended with: a `body` (`ReactNode`) slot for counts, totals and alerts; an `onConfirm` that may return a `Promise` — while it's pending, the confirm button shows a `Spinner` and both footer buttons are disabled, but the dialog itself is **never auto-closed** — closing on success/failure is entirely the caller's decision (call `onClose`/the modal store's `close()` once the promise settles); if that promise **rejects**, the modal clears its busy state and sends the device to sign-in via `goToSignIn()` (`contracts/server-actions.md` "Boundary": a rejected call is treated like UNAUTHORIZED), so callers don't need their own catch for that path; a synchronous `onConfirm` keeps the old behaviour (closes right after). Also takes `confirmDisabled` (disables Confirm without touching Cancel) and `hideConfirm` (hides Confirm entirely, leaving only Cancel — the caller sets `cancelText` to match, e.g. `'Close'` for a blocked state). | SCR-08 (delete-account), SCR-14 (blocked delete), SCR-15 (totals-changed), plus every simple delete confirmation (products, bank accounts, customers, sender profiles, email change) |
| `CopyButton` | `components/ui/copy-button.tsx` | An icon `Button` (`size="icon"`, `aria-label` "Copy {what}") that writes its `value` prop with `navigator.clipboard.writeText`. On success the icon swaps to a check and the label to "Copied" for 2 s, announced via an `aria-live="polite"` region. If the clipboard is unavailable or refused: `toast.error` "Couldn't copy. Select the text and copy it by hand." Never logs or sends `value`. | Connect your AI page (setup snippets, example prompts; key reveal in T21) |
| `IssuedDetailsCard` | `components/invoice-editor/issued-details-card.tsx` | A `Card` (title + icon, "As issued on this invoice.") that prints an issued invoice's recorded details as text lines, skipping empty ones, with an optional second labelled block (the bank account). Read-only: no picker, no input. | Invoice editor `issued` / `cancelled` modes — the From and To blocks (invoice-integrity screens.md SCR-02, ADR-0001) |
| `AmountInput` | `components/invoice-editor/amount-input.tsx` | A text `Input` (`data-slot="amount-input"`, `inputMode="decimal"`) for money, quantity and rate fields. Props: `value: string`, `onChange(raw: string)`, plus the usual input props (`id`, `aria-*`, `disabled`, `className`, `onBlur`). `.` is the only decimal separator: a change containing `,` is dropped whole, so the field keeps its text and `onChange` never sees a comma (a pasted `12,5` is not turned into `125`). A rejected comma shows a hint beside the field ("Use a decimal point (.) as the separator.", a `FieldDescription` inside an `aria-live="polite"` region, merged into the input's `aria-describedby` with any caller-provided ids) that clears when the field loses focus. Otherwise it passes the raw text through, so drafts like `12.` stay as typed; parsing and validation stay with `useNumberDraft` / the form schema. | Invoice editor: line price and quantity (`InvoiceItemFields`), discount, shipping and tax rate (`SummarySection`) |
| `PdfPreparingStatus` / `PdfPreparingSpinner` | `components/invoices/pdf-preparing-status.tsx` | The one preparing indication for a PDF trigger (editor-ux T41, AC-01): `PdfPreparingStatus busy` renders an sr-only `role="status"` "Preparing PDF…" (nothing when not busy); `PdfPreparingSpinner` is an `aria-hidden` `Loader2` `animate-spin` that replaces the trigger icon. The trigger itself also sets `aria-busy`. | Row actions (list/dashboard), related-invoices list, preview dialog Download/Print, editor Download/Print |
| `ConversationList` | `components/ai/conversation-list.tsx` | The AI section's list column (SCR-01): `ConversationList({ conversations: Page<ConversationSummary>, timeZone, onDelete })`. Rows are `Item`s linking to `/ai/{id}` (title truncated, full text as `title` attribute, last-message day "d MMM yyyy" in the account zone) with a per-row delete icon `Button`; a "New conversation" link to `/ai`; a "Conversation actions" `DropdownMenu` with "Delete all" (hidden when empty); `Empty` "No conversations yet"; `?page=N` pagination links (`aria-current="page"`); the fixed 90-day retention notice, always shown. Deletion is reported through `onDelete`, never done here; the page renders it through `ConversationListClient`, which owns `onDelete` (a function prop cannot cross the RSC boundary). | `/ai` page (T18); delete dialog wiring in T30 |
| `AssistantMark` | `components/ai/assistant-mark.tsx` | `AssistantMark({ mark })`: a small outline `Badge` "AI" that is a `Tooltip` trigger (focusable) naming the Assistant: "Created by the in-app chat" for `CHAT`, "Created by {keyName}" for `PERSONAL_KEY` (the key's name as at creation). Renders nothing for `null`. | Invoice list draft rows (`InvoicesDataTable`), editor header beside the Draft badge (AC-23) |
| `AllowanceNotice` | `components/ai/allowance-notice.tsx` | `AllowanceNotice({ state: AllowanceState, usedUpMessage?, handMadeLink? })`. Counter mode (`left > 0`): one muted line "{left} of 30 messages left today". Used-up mode (`left = 0`): "You've used today's 30 messages", "They renew {when} your time." ({when} in the account zone: "at 00:00", "tomorrow at HH:mm" or "at HH:mm"), the Personal-key note, outline links "Connect your own AI client →" and, with `handMadeLink`, "Create it by hand →". `usedUpMessage` (the 429 text) replaces the first two lines verbatim. | `StartPanel`; chat used-up state (T33) |
| `StartPanel` | `components/ai/start-panel.tsx` | `StartPanel({ state, start?: 'draft', onSend })` (client). A `Card` with the heading ("Ask about your invoices" / "Draft an invoice"), outline example `Button`s (four questions, or one draft chip), a `Textarea`, "Send" and the counter. An example fills and focuses the textarea and never sends. At `left = 0` only `AllowanceNotice`. The page renders it through `StartPanelClient`, which owns `onSend`. | `/ai` page (T22); chat island wiring in T33 |
| `ChatLink` | `components/ai/chat-link.tsx` | `ChatLink({ link: AppLink, state?: LinkedInvoiceState })`. Invoice link: a draft "INV-0043 · Draft", an issued one its number plus `InvoiceStatusBadge`, both opening the editor; `UNAVAILABLE` "INV-0043 · No longer available" as plain text, never an anchor; with no state it is plain text, never presented as a draft. Page link: "{app map title} →" to `appPageRoute(page, senderProfileId)`. Targets never come from model-written text. `MessageList` (`components/ai/message-list.tsx`) renders messages with it as plain text (`whitespace-pre-wrap`); `ConversationHeader` holds the title, "New conversation" and the "Conversation actions" menu (page uses `ConversationHeaderClient`, which owns `onDelete`). | `/ai/[conversationId]` (T23); chat island (T33) |
| `DraftCard` | `components/ai/draft-card.tsx` | `DraftCard({ card: DraftCardView })` (client). Root `id="draft-card-{id}"`. Shows the proposal with a source label per value ("(default)", "(you named it)", price source, "Not linked to a product"), "Defaults used" when non-empty and one "Create draft" `Button` that calls `createDraftFromCard` itself (`Spinner` while pending, a second press cannot fire). Collapses to "Draft invoice · {Customer} · {total}" with a "Replaced" / "Outdated" `Badge` and, for an `OUTDATED` result, renders the returned card right below. Created, issued-since and unavailable states, needs-answers `Alert`; failures through `toast.error`, `UNAUTHORIZED` through `goToSignIn`. Never needs a message (AC-11c). | `/ai/[conversationId]` card slot (T28) |

## Notes

- Every caller that passes an async `onConfirm` is responsible for closing the dialog once that
  promise settles (both on success and on failure) — see
  `docs/features/architecture-hardening/_review/review-2026-09-27.md` F-40 for the regression this
  guards against.
