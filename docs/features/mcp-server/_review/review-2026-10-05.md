### Stage 1 — AC compliance

**F-01 · High · Fix now → T26**

- **Finding:** `getInvoiceEditorData` puts the derived status into `initialData`. The editor sends the whole `formData` to `updateInvoice`, and `applyStatusChange` returns `next` unchanged, so any edit-and-save of a past-due PENDING invoice stores OVERDUE for good. `updateInvoice` never applies `refusesManualStatus`.
- **Cite:** `lib/services/invoices/editor-data.ts:84`, `store/invoice-editor-store/use-invoice-editor-store.ts:424-432`, `lib/services/invoices/invoices.ts:644-664`, `lib/helpers/invoice-status.ts:29-43`; the read-only test `tests/integration/services/invoices/derived-status.test.ts:119-127`.
- **AC:** AC-24 ("its stored status is unchanged"), ADR-0005.

**F-02 · High · Fix now → T25**

- **Finding:** the overdue rule takes a due date's calendar day as its UTC day (`toISOString().slice(0,10)`, `"dueDate"::date`), but the editor stores the browser's local midnight (`z.coerce.date()` on the Calendar's `Date`). For a Kyiv Freelancer a due date of 15 Oct is stored as `2026-10-14T21:00Z`: the invoice is overdue on its own due date, days overdue is +1, and Assistant rows report `dueDate: "2026-10-14"`. Every test seeds `T00:00:00Z`, which hides it.
- **Cite:** `lib/services/_shared/overdue.ts:29-31,45,50-55`, `lib/validations/invoice.ts:94`, `components/invoice-editor/invoice-details-section.tsx:158`, `store/invoice-editor-store/helpers.ts:333`; also `lib/services/dashboard/assistant-reads.ts:126,216`, `lib/services/invoices/assistant-search.ts:170-171,220`, `lib/services/invoices/find-by-reference.ts:163`.
- **AC:** AC-12, AC-23, AC-23b, AC-24; spec §1 ("a due date is a calendar day … without any shift").
- **Owner decision:** store issue and due dates as calendar days (`yyyy-MM-dd` → `T00:00:00Z`), backfill existing rows from each owner's saved zone, and compare everywhere by calendar day.

**F-03 · High · Fix now → T25**

- **Finding:** "due within the period" compares `dueDate` against zone-local midnight instants (`periodBounds`), which disagrees with the overdue rule's calendar day. With calendar-day due dates, a New York Freelancer's "this month" misses the invoice due on the 1st and includes the one due on the 1st of next month. Parity holds (same SQL), but both surfaces are wrong; no western-zone period test exists.
- **Cite:** `lib/services/dashboard/queries.ts:64-65,430-433`, `lib/services/dashboard/period.ts:77-82`.
- **AC:** AC-14, AC-15; sad §8 ("due dates are calendar days compared without shift").

**F-04 · High · Fix now → T27**

- **Finding:** `takeMcpKeyCall` is charged once per POST, but the SDK's `WebStandardStreamableHTTPServerTransport` accepts arrays of up to `MAX_BATCH_SIZE = 100` messages and dispatches each. One counted call can run 100 `tools/call`s (6 000/min per key instead of 60).
- **Cite:** `app/api/mcp/route.ts:20-25`, `lib/mcp/authenticate.ts:119-124`, `node_modules/@modelcontextprotocol/sdk/dist/esm/server/webStandardStreamableHttp.js:504-511`.
- **AC:** AC-11; `contracts/openapi.yaml:158` ("batches are not accepted").

**F-05 · Medium · Fix now → T28**

- **Finding:** the dashboard builds its default/preset period from the browser `tz` cookie (`getRequestTimeZone()`), while overdue and the Assistant's `this-month` use the account zone. After a saved zone differs from the browser's, the dashboard month and the Assistant month differ. The day-boundary test passes an explicit period and so bypasses the page. `app/(protected)/invoices/page.tsx:22` also still reads the cookie.
- **Cite:** `app/(protected)/dashboard/page.tsx:91-92`.
- **AC:** AC-22, AC-23; ADR-0006 ("the cookie survives only as the first-visit seed").

**F-06 · Medium · Fix now → T29**

- **Finding:** `candidate()` returns invoice candidates as `{invoiceId, name, detail}` and drops the `senderProfile`, `customer` and `issueDate` that `find-by-reference.ts:259-266` already builds. The contract requires `InvoiceCandidate` with `additionalProperties: false`; the Assistant cannot pass `senderProfile` back without parsing a string. The test only checks the count.
- **Cite:** `lib/mcp/answers.ts:101-110`; `contracts/openapi.yaml:838-848`; `tests/integration/api/mcp-lookup-tools.test.ts:205-206`.
- **AC:** AC-20.

**F-07 · Low · Fix now → T31**

- **Finding:** summary currencies and dashboard tabs use `status <> 'DRAFT'`, so a currency that only appears on cancelled invoices gets an all-zero entry or tab.
- **Cite:** `lib/services/dashboard/queries.ts:37,485`.
- **AC:** AC-15; CONTEXT "Issued invoice … NOT a cancelled invoice"; ADR-0008.

**F-08 · Low · Fix now → T29**

- **Finding:** the route's 500 body ("invoiceFlow could not complete this call…", `data.code: FAILED`) differs from the contract's `ServerFailure`.
- **Cite:** `app/api/mcp/route.ts:27-37`; `contracts/openapi.yaml` `ServerFailure`.
- **AC:** n/a (contract fidelity).

**F-09 · Low · Fix now → T30**

- **AC:** AC-05, AC-01.

### Stage 2 — quality

**F-10 · Medium · Fix now → T30**

- **Finding:** any store error in the key check returns `REFUSED` (including a failed throttled `lastUsedAt` update). The Assistant gets the "ask the Freelancer to create a key" 401, and the call counts as a refused key check against the network source, so a short outage can block a busy source for 5 minutes.
- **Cite:** `lib/services/personal-keys/authenticate.ts:39-49`, `lib/mcp/authenticate.ts:113-117`.
- **AC:** AC-07; §6 NFR (fail closed).

**F-11 · Medium · Fix now → T32**

- **Finding:** `OVERDUE_STATUS = 'overdue'.toUpperCase()` exists only to stop `/\bOVERDUE\b/` in the literal scan from matching. Exported from `types/`, it lets a future service `where: { status: OVERDUE_STATUS }` pass the guard ADR-0005 relies on. The `as Record<…>` cast on `invoiceStatusConfig` also disables exhaustiveness.
- **Cite:** `types/invoice/types.ts:187-190,203-209`; `tests/unit/services/overdue-literal-scan.test.ts:14`.
- **AC:** AC-12 / ADR-0005.

**F-12 · Medium · Fix now → T34**

- **Finding:** `test-plan.md` declares e2e / e2e-through-UI rows for AC-01, AC-02, AC-06, AC-09, AC-19, AC-22 and AC-24 ("run before ship"), but `tests/e2e/` has none and no task owns them. Nothing exercises the real proxy or real navigation.
- **Cite:** `docs/features/mcp-server/test-plan.md` (those rows); `tests/e2e/`.
- **AC:** AC-01, AC-02, AC-06, AC-09, AC-19, AC-22, AC-24.

**F-13 · Low · Fix now → T29**
