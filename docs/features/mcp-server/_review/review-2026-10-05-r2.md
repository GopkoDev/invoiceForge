### Stage 1 — AC compliance

**H-01 · High · Fix now → T40**

- **Finding:** an editor save while the account has no saved zone stores the wrong day permanently.
- **Why it happens:** the `(invoice-editor)` layout never mounts `<TimeZoneCookie />`, so a first private visit to `/invoices/<id>/edit` seeds nothing. That visit can come from the Assistant's invoice link, a bookmark, or the sign-in return path.
- **Example:** a Kyiv legacy value `2026-10-14T21:00Z` shows as 14 Oct. Any save writes `2026-10-14T00:00Z`. The lazy normaliser then skips it because it is already a UTC midnight, so 15 Oct becomes 14 Oct for good.
- **Second trigger:** a stale editor tab saved after another tab has saved the zone.
- **Cite:** `app/(invoice-editor)/layout.tsx:1-19`, `app/(protected)/layout.tsx:32`, `lib/helpers/session-actor.ts:24-26`, `store/invoice-editor-store/helpers.ts:333-352`, `lib/services/invoices/invoices.ts:667-668`, `lib/services/_shared/invoice-calendar-days.ts:24-30`.
- **AC:** AC-12, AC-19, AC-23b, AC-24; G-01; spec §1.
- **Suggested:**
  - Mount the cookie in the editor layout.
  - In `updateInvoice`, leave `issueDate`/`dueDate` untouched when the submitted day equals `utcDateToDay(stored)` and the stored value is not a UTC midnight.
  - Add an integration test: no zone, a legacy Kyiv value, a notes-only save, then the zone is saved, and the due day is still the 15th.

**H-02 · Medium · Pre-ship check (spec §8)**

- **Finding:** migration `20261005100000_normalize_invoice_calendar_dates` was edited in place. d836bd0 had a UTC fallback; fba8a91 replaced it under the same folder name.
- **Risk:** any kept database that applied the d836bd0 text (dev `.env`, preview, a CI snapshot) has:
  - a checksum mismatch;
  - dates for zone-less accounts already cut at their UTC day.
- **Cite:** `prisma/migrations/20261005100000_normalize_invoice_calendar_dates/migration.sql`.
- **AC:** AC-12, AC-23b; G-01.
- **Owner decision:** before ship, check `_prisma_migrations` (name and checksum) on every kept database, after confirming which host each env file targets. Repair any database that ran the old text on purpose. Production runs only the fba8a91 text.

### Stage 2 — quality

**H-03 · Medium · Fix now → T41**

- **Finding:** Sentry transaction events for `/api/mcp` can carry `request.headers.authorization` (a full `ifk_` key) and `request.data` (tool arguments).
- **Why it happens:** `scrubMcpRequest` runs only in `beforeSend`, and `tracesSampleRate` is 0.1 in production.
- **Cite:** `sentry.server.config.ts:100,112-113`; `@sentry/core` `integrations/http/server-subscription.js:48-58`, `integrations/requestdata.js:27,44-49`.
- **AC:** n/a. Breaks `sad.md:769` ("Sentry scrubbing extends to request headers on /api/mcp").
- **Suggested:** add `beforeSendTransaction: scrubMcpRequest` and `httpIntegration({ ignoreIncomingRequestBody })` for `/api/mcp`, with unit tests.

**H-04 · Medium · Fix now → T42**

- **Finding:** the dashboard chart's axis ticks and tooltip parse calendar-day strings with `new Date(value)`. Any browser west of UTC therefore labels the 1 Oct point "Sep 30".
- **Cite:** `components/dashboard/chart/dashboard-chart.tsx:105-121`; `lib/services/dashboard/dashboard.ts:125`.
- **AC:** AC-22, AC-23 (SCR-01).
- **Suggested:** format with `formatStoredDay`, and add a component test under `TZ=America/Los_Angeles`.

**H-05 · Low · Fix now → T40**

- **Finding:** the server-action and service schema still accept a `Date` for issue and due dates and silently keep its UTC day. A stale pre-deploy bundle or a future caller would store the day before for zones east of UTC.
- **Cite:** `lib/validations/invoice.ts:26-36`, `lib/actions/invoice-actions/invoice-actions.ts:51-69`.
- **AC:** AC-12, AC-23b.
- **Suggested:** the server accepts only `yyyy-MM-dd`; the `Date` branch moves to a client-only schema.

**H-06 · Low · Fix now → T41**

- **Finding:** failures inside the SDK's `handlePostRequest` are missed. They become a 400 "Parse error" with `String(error)` in `data`, never reach Sentry, and are left out of the ≤ 1 % server-failure KPI.
- **Cite:** `app/api/mcp/route.ts:35-42`; `@modelcontextprotocol/sdk` `webStandardStreamableHttp.js:707-710`.
- **Suggested:** set `transport.onerror` to report to Sentry, and drop the raw error text from the response.

**H-07 · Low · Fix now → T41**

- **Finding:** a client that aborts mid-upload makes `reader.read()` throw. The route then answers 500 and reports it to Sentry, which inflates the server-failure KPI.
- **Cite:** `app/api/mcp/route.ts:43-44,100-110`.
- **Suggested:** catch read errors in `readJsonBody` and return a client-error refusal without reporting it.

**H-08 · Low · Fix now → T42**

- **Finding:** a dashboard preset clicked in a tab left open past midnight uses the `today` fixed at server render, so "This Month" can send last month.
- **Cite:** `components/dashboard/header/dashboard-filters.tsx:78-87`, `app/(protected)/dashboard/page.tsx:103`, `dashboard-header.tsx:64-69`.
- **AC:** AC-22, AC-23.
- **Suggested:** send `?preset=<name>` and resolve it on the server in the account zone.

**H-09 · Low · Fix now → T42**

- **Finding:** the pressed preset is always `this-month` after a load or reload, whatever `appliedPeriod` is.
- **Cite:** `components/dashboard/header/dashboard-filters.tsx:74`.
- **AC:** AC-22 (SCR-01).
- **Suggested:** work out the pressed preset from `appliedPeriod` and `today`, falling back to `custom`.

**H-10 · Low · Fix now → T40**

- **Finding:** lazy normalisation is tested only for a zone east of UTC. The lazy SQL is a separate copy of the migration expression, so the two could drift without a test noticing.
- **Cite:** `tests/integration/services/profile/time-zone.test.ts:86-163`, `lib/services/_shared/invoice-calendar-days.ts:21-35`.
- **AC:** AC-12, AC-23b.
- **Suggested:** add a NULL → `America/New_York` case, e.g. `2026-10-16T02:00Z` becomes the 15th.

**H-11 · Low · Fix now → T42**
