### Stage 1 — AC compliance

**I-01 · High · Fix now → T44**

- **Finding:** an editor save after the zone was seeded writes the stale UTC day permanently. `keepUnchangedLegacyDay` compares against the row read at save time, not the dates the editor loaded.
- **Scenario:**
  1. The account has no saved zone, and this browser has no `tz` cookie (a new device, or the Assistant's AC-19 link). The invoice has a Kyiv legacy due date `2026-10-14T21:00Z`.
  2. The first render seeds nothing. The editor store is set up once and shows 14 Oct.
  3. `<TimeZoneCookie />` sets the cookie and calls `router.refresh()`. The refreshed render runs `actingFreelancerFromSession`, and `seedTimeZoneIfEmpty` normalises the row to `2026-10-15T00:00Z`. The editor is not set up again.
  4. The user saves after editing only the notes, which submits `'2026-10-14'`.
  5. `existingInvoice.dueDate` is now a UTC midnight, so the submitted 14th is written. The issue date moves the same way.
- **Same path:** the save action does the seed itself, or a stale tab is saved after another tab saved the zone.
- **Why the tests miss it:**
  - The tests use a zone-less actor, so no seed happens between load and save.
  - The race test passes only because the save reads before the normaliser commits.
- **Wrong text:** the comment at `invoices.ts:519-525` and ADR-0009 `:41` are false. `server-actions.md:163`, `data-model.md:104` and `screens.md:292` repeat the same guarantee.
- **Cite:**
  - `lib/services/invoices/invoices.ts:526-530,550-553,688-697`
  - `app/(invoice-editor)/layout.tsx:17`
  - `components/time-zone-cookie.tsx:33-34`
  - `components/invoice-editor/invoice-editor.tsx:69-76`
  - `lib/helpers/session-actor.ts:24-26`
  - `lib/actions/invoice-actions/invoice-actions.ts:67`
- **AC:** AC-12, AC-19, AC-23b, AC-24; reopens H-01.
- **Suggested:**
  - The save payload carries the instants the editor loaded (`loadedIssueDate` / `loadedDueDate`), and the server compares against them.
  - Add an integration test: zone seeded after load, then a notes-only save; the due day is still the 15th. Add the stale-tab case as well.
  - Correct the docs listed under "Wrong text".

**I-02 · Medium · Fix now → T45**

- **Finding:** the SDK catch-all failure answers `400 / -32700 "Parse error"`. The contract `ServerFailure` defines 500 / `-32603` "Something went wrong in Invoice Forge. Try again."
- **Impact:** the Assistant client is told its own JSON was malformed, although the route had already parsed it, so it does not retry. The test checks only the Sentry report and that the raw text is gone.
- **Cite:** `app/api/mcp/route.ts:49,70-84`; `contracts/openapi.yaml:415,529-537`; `tests/unit/api/mcp-route-transport-errors.test.ts:52-58`.
- **AC:** AC-07 (contract fidelity).
- **Owner decision:** the code moves to the contract. The catch-all returns `ServerFailure` 500, and the test asserts the status and the body.
